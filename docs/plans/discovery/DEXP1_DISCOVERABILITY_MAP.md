# DEXP-1: Discoverability Map

**NOT A MASTER PLAN.** This is a finite experiment specification for the discovery workstream. `CURRENT_EXECUTION_PLAN.md` owns cross-project sequencing and `doctrine/ROADMAP.md` owns milestone status. Nothing in this document is a milestone, and nothing in it is implemented.

**Spec version:** v1.0, written 2026-09-30. Status: FROZEN AS TEXT, BLOCKED (see section 9). Once a run's preregistration manifest is committed, the values in this document are binding for that run; any change is a new spec version and a new run.

**Parent document:** The Turing Discovery Gap Conjecture, Revision 6, 2026-09-30 (cited below as "Rev 6"). Rev 6 proves Claim A: hard worlds exist if one-way functions exist. It gives no positive conditions under which a world is discoverable. DEXP-1 measures those conditions on synthetic worlds, and section 7 states the modest mathematical result the measurements are meant to inform. Current facts are in `DISCOVERY_CURRENT_STATE.md` in this folder.

## 1. Question

On synthetic worlds generated by short programs from one declared, bounded program family, when does discovery succeed and when does it fail, as a function of shared structure, composition depth, observation noise, active queries and compute?

The output is a **map**, not a single verdict: success rate and net Turings for each combination of factor levels, plus the frontier where success gives way to failure.

## 2. Accounting (inherited from Rev 6, not redefined)

- **Unit.** T(M;B,D,X) = [L(B) + L(D|B,X)] − [L(M) + L(D|M,X)], in bits, prefix-free codes, lossless decoding (Rev 6 Appendix A).
- **Decoder rule.** Anything the decoder uses beyond the input locations X is charged in L(M), including any library the learner carries.
- **Efficient coding.** Encoding and decoding run in polynomial time; otherwise the submission scores zero.
- **Gain density.** Turings per evaluated bit is reported with every total.
- **Two accounts.** Bits in the Turing account; candidate evaluations in the budget account; no conversion.
- **Available gain and success** (Rev 6 Appendix B, step 6). The available gain of a task is the frozen evaluation score of the generating program itself, with its declared noise model, under the same profile and baseline. A learner succeeds on a task if its frozen model scores at least **10 percent** of the available gain, the fraction Rev 6 proposes.

## 3. Worlds

Each task is one learning problem in the form of Rev 6 Appendix B:

| Item | Frozen value for v1.0 |
|---|---|
| Size parameter | n = 32 |
| Input space X | 2^16 input locations, uniform input distribution |
| Hidden world | one program drawn from the declared family F (section 7.1) by sealed seed, plus additive noise of declared standard deviation sigma before quantization |
| Quantizer | 256 uniform bins over [-5, 5], out-of-range values clipped to edge bins (the CEXP-1 value) |
| Baseline | uniform over quantization bins, 8 bits per outcome (the CEXP-1 value) |
| Discovery observations | 1,024 outcomes per task in total, split between passive draws and adaptive queries by factor Q |
| Freeze | the learner outputs one model and is frozen when its observation and compute budgets are spent |
| Evaluation | m = n^2 = 1,024 fresh, pairwise distinct input locations never revealed during discovery, drawn after the freeze |

**Why these numbers.** n = 32 makes m = n^2 = 1,024 evaluated outcomes, matching Rev 6's evaluation rule, and makes the discovery observation count equal to the evaluation count. A 2^16 domain is 32 times the number of revealed plus evaluated locations, so fresh distinct evaluation inputs are always available and exhaustive memorization of the domain is outside the observation budget.

## 4. Factors and levels

| Factor | Symbol | Levels (frozen for v1.0) | Meaning |
|---|---|---|---|
| Shared structure | H | 0, 1/3, 2/3, 1 | fraction of each task's components drawn from a pool shared across the tasks of a sequence; the rest come from a pool private to that task |
| Composition depth | K | 1, 2, 3, 4 | nesting depth of component applications in the hidden program |
| Observation noise | sigma | 0, 0.05, 0.25, 1.0 | standard deviation of additive Gaussian noise, in output units, before quantization (0.05 is about one bin width) |
| Active query share | Q | 0, 256, 512 | how many of the 1,024 discovery observations are adaptive queries chosen by the learner; the rest are passive draws |
| Compute budget | C | 2,000; 20,000; 200,000 | candidate evaluations per task, one candidate scored against the task's observations; 20,000 is the CEXP-1 value |

The total observation count is the same at every Q level, so a Q effect measures the value of choosing observations, not of having more of them.

## 5. Design

A full factorial over all five factors is 576 cells. v1.0 declares a fraction:

- **Core grid:** full factorial over H x K x sigma (64 cells), at Q = 0 and C = 20,000.
- **Query and compute sweep:** the 8 corner cells of the core grid (H in {0, 1}, K in {1, 4}, sigma in {0, 1.0}), each run at all 9 combinations of Q x C. One of the 9 (Q = 0, C = 20,000) is already in the core grid, so the sweep adds 64 cells.
- **Total:** 128 cells.

**Why this fraction.** The three structural factors (H, K, sigma) define the world and are the map's main axes, so they get every combination. Q and C are resources a learner spends; their effect is expected to be largest at the extremes of difficulty, so they are swept where the core factors are most and least favourable. Interactions of Q and C with intermediate core levels are not estimated in v1.0 and are not claimed.

**Sequences and learners.** Each cell is run as sequences of 8 tasks drawn from the cell's world settings. Two learners run every sequence, paired by seed, with identical discovery procedure and hyperparameters:

- **Reset:** carries nothing across tasks.
- **Reuse:** CEXP-1's library learner, with Claim C's admission rule (positive net Turings on the task's sealed evaluation, description length charged) and all library costs charged under the decoder rule.

Tasks 1 to 4 of a sequence build the Reuse library; tasks 5 to 8 are the scored tasks of the map. Shared structure H can only matter to the Reuse learner; the paired Reset learner shows the cell's difficulty without carried knowledge.

**Replication:** 20 sequences per cell per learner, 80 scored tasks per cell per learner. With 80 scored tasks, a 95 percent interval on a success proportion has half-width at most about 0.11 before allowing for correlation within a sequence. Intervals are computed by bootstrap over sequences, which accounts for that correlation.

**Pilot fallback.** Before the freeze, one sequence of each of the 9 sweep combinations at the hardest corner cell is run on development seeds to measure compute cost. If the measured cost of the full design exceeds the compute allocation declared in the preregistration manifest, replication is reduced to 10 sequences per cell. Levels and cells never change. This choice is made and recorded before any sealed data exist.

## 6. Outcomes and analysis

Per cell, per learner, over the scored tasks:

- **Success rate:** fraction of scored tasks reaching at least 10 percent of the available gain, with a 95 percent percentile bootstrap interval over sequences (10,000 resamples).
- **Net Turings:** mean and full distribution, with gain density.
- **Fraction of available gain achieved:** mean of (task score / available gain), with interval.
- **Reuse benefit:** Reuse minus Reset, paired by sequence, for success rate and net Turings, with intervals.
- **Budget used to first success:** where the learner records it, the candidate evaluations spent before its final model first appeared.

Reported as a map:

- Three two-way tables over the core grid (H x K, K x sigma, H x sigma), each averaged over the third factor.
- One Q x C table at each of the 8 corner cells.
- **Discoverability frontier:** for each (K, sigma) pair, whether the Reset success rate interval lies above 0.5, below 0.5, or contains it, at C = 20,000; and for each corner cell, the smallest C level at which the success interval lies above 0.5, or "none".

**Declared expectations** (directions only, written before the run so that surprises are visible): success falls as K and sigma rise; success rises with C and with Q; the Reuse benefit rises with H and is near zero at H = 0. A reversal of any of these is reported prominently. None of these directions is a hypothesis the run is said to confirm; DEXP-1 is a measurement, and its map is the result.

## 7. The result to prove

This section states a conjecture and its proof obligation. **Nothing here is proved.**

### 7.1 Definitions

- **Primitive set I.** A finite, declared set of primitives over fixed-point values: arithmetic, comparison, conditional, and composition of components. I contains no bitwise mixing, hashing or keyed primitive.
- **Bounded family F(I, l, s).** All programs over I of length at most l symbols, run with an execution limit of s steps; a program that exceeds s steps outputs a declared default value. Length is measured under the profile's program description code.
- **Behavioral class.** Two programs are in the same class if they give the same output on every input in X. Recovering the generating program is not required; any program in its class is as good (Rev 6: any effective predictor counts).
- **N_F.** The number of behavioral classes in F.
- **Input separation.** delta(F, mu) = the minimum, over every pair of distinct classes, of the probability under the input distribution mu that the two classes give different outputs.
- **Channel separation.** h_min = the minimum, over every pair of distinct output values a and b that some program in F can produce, of the squared Hellinger distance between the quantized noisy outcome distributions at a and at b.
- **l\*.** The length of the shortest program in the hidden world's behavioral class.

### 7.2 Scope

Claim A shows that worlds generated by keyed pseudorandom functions resist every efficient learner. The bounded family is chosen so that a positive bound is possible at all: its primitive set excludes keyed mixing, and the bound below is exponential in l\*. It gives efficient discovery only when l\* is at most logarithmic in the compute budget. A Claim A world needs a key of length n, so l\* grows with n and the bound does not apply. The conjecture does not contradict Claim A; it marks the region where Claim A's barrier is absent.

### 7.3 Conjecture D1: observations distinguish members

If delta(F, mu) > 0 and h_min > 0, then for every eta in (0, 1) there is a universal constant c such that

m_0 = ceiling( c * (ln N_F + ln(1/eta)) / (delta(F, mu) * h_min) )

passive observations suffice for the maximum-likelihood behavioral class to equal the hidden class with probability at least 1 − eta. In the noiseless case (sigma = 0) the expected form is m_0 = ceiling( (ln N_F + ln(1/eta)) / delta(F, mu) ).

*Proof obligation:* a proof with an explicit c; for the noiseless case the expected route is a union bound over classes in the style of Valiant (Rev 6 reference 15), and for the noisy case a likelihood-ratio concentration bound. A counterexample family is equally acceptable as an outcome.

### 7.4 Conjecture D2: search bound

Under the conditions of D1, with at least m_0 observations, and with available gain bounded away from zero, a learner that enumerates F in nondecreasing length and outputs the candidate with the smallest two-part code length L(M) + L(observations | M) succeeds, at the 10 percent fraction, with probability at least 1 − eta − eta', using at most

B(l\*) = |I| + |I|^2 + ... + |I|^(l\*)

candidate evaluations, each costing at most m_0 * s execution steps in the operating account. Here eta' bounds the probability that the sealed evaluation draw, rather than the choice of model, causes the failure.

*Proof obligation:* show that, once the true class is reached in the enumeration, no shorter wrong class has a smaller two-part code length except with probability eta, and bound eta' from the evaluation size m = n^2.

### 7.5 Follow-on question: do learned abstractions improve the bound?

Give the learner a frozen library Lambda of k components with total description length L(Lambda), charged under the decoder rule. Programs are now written over I plus Lambda, the hidden class has shortest length l\*\_Lambda, and the enumeration bound becomes B\_Lambda = (|I| + k) + ... + (|I| + k)^(l\*\_Lambda).

**Question:** under which shared-structure conditions is B\_Lambda much smaller than B(l\*), while the learner's net Turings, after paying L(Lambda) in every task's model, still reach the success threshold? This is the bound-level form of the question CEXP-2 measures.

### 7.6 How DEXP-1 bears on D1 and D2

For every cell, the generator records |I|, the length of the generating program (an upper bound on l\*), N_F where it is computable, and the empirical delta on the evaluation inputs. A cell where D1's conditions hold, the compute budget exceeds B at the generating program's length, and the success rate interval lies below 1 − eta is a **counterexample candidate** and is handed to the proof effort. Experiments cannot prove D1 or D2; they can expose weaknesses in their formulation, as Rev 6 says of Claims A and B.

## 8. Preregistration and deviations

- A preregistration manifest is committed before any sealed data exist. It holds this spec version, the bound profile id and digest, the program description code, the primitive set I, l and s for each K level, the component pools and the sharing rule for H, the noise model, the query interface, the discovery procedure and its hyperparameters, the seed derivation rule, the compute allocation for the pilot fallback, and the analysis above.
- Evaluator-only details follow the commit-then-reveal rule of the Brownian calibration program (`docs/brownian-calibration-explainer.md`): fingerprint first, contents after the run.
- The EXP-001 void rule applies: void only for an infrastructure failure before any sealed score of that sequence, identical-input retry at most 3 times, every void published.
- Any deviation after the first sealed sequence voids the run's claim to be DEXP-1 v1.0. The run stays in the record.
