# DEXP-1: Discoverability Map

**NOT A MASTER PLAN.** This is a finite experiment specification for the discovery workstream. `CURRENT_EXECUTION_PLAN.md` owns cross-project sequencing and `doctrine/ROADMAP.md` owns milestone status. Nothing in this document is a milestone, and nothing in it is implemented.

**Spec version:** v1.0, written 2026-09-30. Status: FROZEN AS TEXT, BLOCKED (see section 9). Once a run's preregistration manifest is committed, the values in this document are binding for that run; any change is a new spec version and a new run.

**Parent document:** The Turing Discovery Gap Conjecture, Revision 6, 2026-09-30 (cited below as "Rev 6"). Rev 6 proves Claim A: hard worlds exist if one-way functions exist. It gives no positive conditions under which a world is discoverable. DEXP-1 measures those conditions on synthetic worlds. Section 7 states two conjectures, D1 and D2, that the measurements are meant to inform; neither is proved. Current facts are in `DISCOVERY_CURRENT_STATE.md` in this folder.

---

## 1. Question

On synthetic worlds generated by short programs from one declared, bounded program family, when does discovery succeed and when does it fail, as a function of shared structure, composition depth, observation noise, active queries and compute?

The output is a **map**, not a single verdict: success rate and net Turings for each combination of factor levels, plus the frontier where success gives way to failure.

## 2. Accounting (inherited from Rev 6, not redefined)

- **Unit.** T(M;B,D,X) = [L(B) + L(D|B,X)] − [L(M) + L(D|M,X)], in bits, prefix-free codes, lossless decoding (Rev 6 Appendix A).
- **Decoder rule.** Anything the decoder uses beyond the input locations X is charged in L(M), including any library the learner carries.
- **Efficient coding.** Encoding and decoding run in polynomial time; otherwise the submission scores zero.
- **Gain density.** Turings per evaluated bit is reported with every total.
- **Two accounts.** Bits in the Turing account; candidate evaluations in the budget account; no conversion.
- **Available gain and success** (Rev 6 Appendix B, step 6). The available gain of a task is the frozen evaluation score of the generating program itself, with its declared noise model, under the same profile and baseline. A learner succeeds on a task if its frozen model scores at least **10 percent** of the available gain, the fraction Rev 6 proposes.
- **Eligibility.** A task is **eligible** only if its available gain is strictly positive. An ineligible task counts as a non-success in success rates, is excluded from the gain-ratio average, and is counted and reported per cell. A task enters the D2 comparison of section 7.6 only if its available gain is at least g_min = 82 Turings, which is 1 percent of the 8,192-bit baseline cost of its 1,024 evaluation outcomes.

## 3. Worlds

Each task is one learning problem in the form of Rev 6 Appendix B:

| Item | Frozen value for v1.0 |
|---|---|
| Size parameter | n = 32 |
| Input space X | 2^16 input locations, uniform input distribution |
| Hidden world | one program drawn from the declared family F (section 7.1) by sealed seed, plus additive noise of declared standard deviation sigma before quantization |
| Output range | every clean (noise-free) output of a drawn program on X lies in [-5, 5]; the generator rejects and redraws any program that violates this, and the rejection count is reported |
| Quantizer | 256 uniform bins over [-5, 5], bin width 10/256 = 0.0390625, out-of-range noisy values clipped to edge bins (the CEXP-1 value) |
| Baseline | uniform over quantization bins, 8 bits per outcome (the CEXP-1 value) |
| Discovery observations | 1,024 outcomes per task in total, split between passive draws and adaptive queries by factor Q |
| Freeze | the learner emits one model and is frozen when its observation and compute budgets are spent (Rev 6 Appendix B, step 4) |
| Evaluation | m = n^2 = 1,024 fresh, pairwise distinct input locations never revealed during discovery, drawn after the freeze |

**Edge bins.** The fraction of sealed outcomes that fall in the two edge bins is reported per cell. A cell whose edge-bin rate exceeds 5 percent is flagged and left out of the frontier (section 6), because clipping there can mask depth and noise effects.

**Why these numbers.** n = 32 makes m = n^2 = 1,024 evaluated outcomes, matching Rev 6's evaluation rule, and makes the discovery observation count equal to the evaluation count. A 2^16 domain is 32 times the number of revealed plus evaluated locations, so fresh distinct evaluation inputs are always available and exhaustive memorization of the domain is outside the observation budget.

## 4. Factors and levels

| Factor | Symbol | Levels (frozen for v1.0) | Meaning |
|---|---|---|---|
| Shared structure | H | 0, 1/3, 2/3, 1 | fraction of each task's component slots filled from a pool shared across the tasks of a sequence; the rest come from a pool private to that task |
| Composition depth | K | 1, 2, 3, 4 | nesting depth of component applications in the hidden program; a depth-K program has exactly s(K) = 3K component slots, so H times s(K) is always a whole number |
| Observation noise | sigma | 0, 0.0390625, 0.25, 1.0 | standard deviation of additive Gaussian noise, in output units, before quantization; the second level is exactly one bin width |
| Active query share | Q | 0, 256, 512 | how many of the 1,024 discovery observations are adaptive queries chosen by the learner; the rest are passive draws |
| Compute budget | C | 2,000; 20,000; 200,000 | candidate evaluations per task; 20,000 is the CEXP-1 value |

The total observation count is the same at every Q level, so a Q effect measures the value of choosing observations, not of having more of them. **Query choice is charged to C:** every scoring of a candidate that the query policy performs to choose the next query costs one candidate evaluation, the same unit as search. A Q level therefore cannot buy uncharged computation.

**H changes overlap only.** The generator draws shared and private components from pools with the same distribution, so the distribution of a single task's law is the same at every H level. H changes only how much tasks in a sequence overlap. The preregistration manifest records a development-seed check of this (matching single-task statistics across H levels).

## 5. Design

A full factorial over all five factors is 576 cells. v1.0 declares a fraction:

- **Core grid:** full factorial over H x K x sigma (64 cells), at Q = 0 and C = 20,000.
- **Query and compute sweep:** the 8 corner cells of the core grid (H in {0, 1}, K in {1, 4}, sigma in {0, 1.0}), each run at all 9 combinations of Q x C. One of the 9 (Q = 0, C = 20,000) is already in the core grid, so the sweep adds 64 cells.
- **Total:** 128 cells.

**Why this fraction.** The three structural factors (H, K, sigma) define the world and are the map's main axes, so they get every combination. Q and C are resources a learner spends; their effect is expected to be largest at the extremes of difficulty, so they are swept where the core factors are most and least favourable. Interactions of Q and C with intermediate core levels are not estimated in v1.0 and are not claimed.

**Sequences and learners.** Each cell is run as sequences of 8 tasks drawn from the cell's world settings. Learners run every sequence of a cell, paired by seed, with identical single-task discovery procedure and hyperparameters:

- **Reset:** carries nothing across tasks.
- **Reuse:** copies Claim C's admission rule (positive net Turings on the task's sealed evaluation, description length charged) and its decoder charging. It is not CEXP-1's implementation: CEXP-1 scores one-step trajectory prediction, DEXP-1 scores a frozen predictor on fresh inputs. CEXP-1 having been run is a gate (section 9), not an identity of implementations.
- **Enumerator:** the learner of Conjecture D2 (section 7.4), no library. It runs only on the 8 corner cells at Q = 0, at all three C levels, so that the counterexample rule of section 7.6 has a learner whose premises can be checked.

Tasks 1 to 4 build the Reuse library. After task 4's sealed score and the admissions it settles, the library is **frozen**; tasks 5 to 8 are the scored tasks of the map and admit nothing. Admission after tasks 1 to 4 uses the Appendix D between-task exception: the scored model of each task is emitted when its budgets are spent and never changed; post-score admission spends only what remains of that task's budget and edits only the library carried into the next task.

**Replication:** 20 sequences per cell per learner, 80 scored tasks per cell per learner. With 80 scored tasks, a 95 percent interval on a success proportion has half-width at most about 0.11 before allowing for correlation within a sequence. Intervals are computed by bootstrap over sequences, which accounts for that correlation.

**Pilot fallback.** After the preregistration manifest states the compute allocation and before any sealed data exist, one development-seed sequence is run at each of the 9 Q x C combinations of the cell H = 0, K = 4, sigma = 1.0, for every learner, to measure cost. If the measured cost of the full design exceeds the declared allocation, replication is 10 sequences per cell; otherwise 20. The chosen number is recorded before sealed data are generated. Levels and cells never change.

## 6. Outcomes and analysis

Per cell, per learner, over the scored tasks:

- **Success rate:** fraction of scored tasks reaching at least 10 percent of the available gain (ineligible tasks count as non-success), with a 95 percent percentile bootstrap interval over sequences (10,000 resamples).
- **Net Turings:** mean and full distribution, with gain density.
- **Fraction of available gain achieved:** mean of (task score / available gain) over eligible tasks, with interval; the ineligible count is reported beside it.
- **Reuse benefit:** Reuse minus Reset, paired by sequence, for success rate and net Turings, with intervals.
- **Budget used to first success:** where the learner records it, the candidate evaluations spent before its final model first appeared.

Reported as a map:

- Three two-way tables over the core grid (H x K, K x sigma, H x sigma), each averaged over the third factor, for Reset and for Reuse separately.
- One Q x C table at each of the 8 corner cells, for each learner separately.
- **Core frontier:** for each core cell (H, K, sigma), whether the Reset success-rate interval at C = 20,000 lies entirely above 0.5, entirely below 0.5, or contains it. The (K, sigma) summary is the same classification at H = 0.
- **Corner frontier:** for each corner cell, each Q level and each learner (Reset, Reuse) separately, the smallest C level at which the success-rate interval lies entirely above 0.5, or "none".
- Cells flagged for edge-bin rate (section 3) are reported but left out of both frontiers.

**Declared expectations** (directions only, written before the run so that surprises are visible): success falls as K and sigma rise; success rises with C and with Q; the Reuse benefit rises with H and is near zero at H = 0. A reversal of any of these is reported prominently. None of these directions is a hypothesis the run is said to confirm; DEXP-1 is a measurement, and its map is the result.

## 7. Conjectures D1 and D2

This section states two conjectures and their proof obligations. **Nothing here is proved.**

### 7.1 Definitions

- **Primitive set I.** A finite, declared set of primitives over fixed-point values: arithmetic, comparison, conditional, and composition of components. I contains no bitwise mixing, hashing or keyed primitive.
- **Bounded family F(I, l, s).** All programs over I of at most l symbols, run with an execution limit of s steps; a program that exceeds s steps outputs a declared default value.
- **Lengths.** l\* and every exponent below count **symbols** from I. The bit length of a program under the profile's program description code is recorded separately and enters only the Turing account.
- **Behavioral class.** Two programs are in the same class if they give the same output on every input in X. Recovering the generating program is not required; any program in its class is as good (Rev 6: any effective predictor counts).
- **N_F.** The number of behavioral classes in F.
- **Input separation.** delta(F, mu) = the minimum, over every pair of distinct classes, of the probability under the input distribution mu that the two classes give different outputs.
- **Channel separation.** h_min = the minimum, over every pair of distinct output values a and b that some program in F can produce, of the squared Hellinger distance between the quantized noisy outcome distributions at a and at b.
- **l\*.** The symbol length of the shortest program in the hidden world's behavioral class.

### 7.2 Scope

Claim A shows that worlds generated by keyed pseudorandom functions resist every efficient learner. The bounded family is chosen so that a positive bound is possible at all: its primitive set excludes keyed mixing, and the bound below is exponential in l\*. It gives efficient discovery only when l\* is at most logarithmic in the compute budget. A Claim A world needs a key of length n, so l\* grows with n and the bound does not apply. The conjectures do not contradict Claim A; they mark the region where Claim A's barrier is absent.

### 7.3 Conjecture D1: observations distinguish members

If delta(F, mu) > 0 and h_min > 0, then for every eta in (0, 1) there is a universal constant c such that

m_0 = ceiling( c * (ln N_F + ln(1/eta)) / (delta(F, mu) * h_min) )

passive observations suffice for the maximum-likelihood behavioral class to equal the hidden class with probability at least 1 − eta. In the noiseless case (sigma = 0) the expected form is m_0 = ceiling( (ln N_F + ln(1/eta)) / delta(F, mu) ).

*Proof obligation:* a proof with an explicit c; for the noiseless case the expected route is a union bound over classes in the style of Valiant (Rev 6 reference 15), and for the noisy case a likelihood-ratio concentration bound. A counterexample family is equally acceptable as an outcome.

### 7.4 Conjecture D2: search bound

The learner does not know l\*. The **Enumerator** therefore runs as follows: it enumerates F in nondecreasing symbol length, scores each candidate once on the observations (one candidate evaluation each), stops when the external compute cap C is spent or F is exhausted, and emits the candidate with the smallest two-part code length L(M) + L(observations | M) among the candidates enumerated so far.

Define B(l\*) = |I| + |I|^2 + ... + |I|^(l\*), the number of candidate evaluations needed to enumerate every program up to length l\*. B(l\*) is the enumeration cost of reaching the hidden class. It is not a stopping certificate: the Enumerator does not know when it has reached the class.

**Conjecture D2.** Under the conditions of D1, with at least m_0 observations, available gain at least g_min, and C at least B(l\*), the Enumerator emits a model in the hidden class with probability at least 1 − eta, and succeeds at the 10 percent fraction with probability at least 1 − eta − eta', where eta' bounds the probability that the sealed evaluation draw, rather than the choice of model, causes the failure. Each candidate evaluation costs at most m_0 * s execution steps in the operating account.

*Proof obligation:* show that, once the hidden class has been enumerated, no other enumerated class has a smaller two-part code length except with probability eta, and bound eta' from the evaluation size m = n^2.

### 7.5 Follow-on question: do learned abstractions improve the bound?

Give the learner a frozen library Lambda of k components with total description length L(Lambda), charged under the decoder rule. Programs are now written over I plus Lambda, the hidden class has shortest symbol length l\*\_Lambda, and the enumeration cost becomes B\_Lambda = (|I| + k) + ... + (|I| + k)^(l\*\_Lambda).

**Question:** under which shared-structure conditions is B\_Lambda much smaller than B(l\*), while the learner's net Turings, after paying L(Lambda) in every task's model, still reach the success threshold? This is the bound-level form of the question CEXP-2 measures.

### 7.6 How DEXP-1 bears on D1 and D2

For every cell, the generator records |I|, the symbol length and bit length of the generating program (the symbol length is an upper bound on l\*), N_F where it is computable, and the empirical delta on the evaluation inputs. For each scored task the evaluator also records whether the emitted model is in the hidden class (by comparing outputs on all of X).

A cell is a **counterexample candidate** to D2 only if every premise is checked: the learner is the Enumerator; the manifest fixes eta and a value of c, and the resulting m_0 is at or below the observations used; every counted task has available gain at least g_min; C is at least B at the generating program's symbol length; and the interval for the **class-identification rate** (not the 10 percent gain rate) lies entirely below 1 − eta. A counterexample candidate is handed to the proof effort. A failure of Reset or Reuse, whose search is not the Enumerator, shows a gap between a practical search and the bound, not a counterexample. Experiments cannot prove D1 or D2; they can expose weaknesses in their formulation, as Rev 6 says of Claims A and B.

## 8. Preregistration and deviations

- A preregistration manifest is committed before any sealed data exist. It holds this spec version, the bound profile id and digest, the program description code, the primitive set I, l and s for each K level, the component pools and the sharing rule for H with its single-task distribution check, the noise model, the query interface and its charging, the discovery procedure and its hyperparameters, the Enumerator's tie-break order, eta and c, the seed derivation rule, the compute allocation for the pilot fallback, and the analysis above.
- Evaluator-only details follow the commit-then-reveal rule of the Brownian calibration program (`docs/brownian-calibration-explainer.md`): fingerprint first, contents after the run.
- The EXP-001 void rule applies, with one counter for the whole run: void only for an infrastructure failure before any sealed score of that sequence, retried with identical inputs; the third void closes the run as inconclusive for infrastructure reasons; every void is published.
- Any deviation after the first sealed sequence voids the run's claim to be DEXP-1 v1.0. The run stays in the record.

## 9. Gates and blockers

DEXP-1 may not start until all of the following hold:

1. **EXP-001 PASS.** Met in successor form: EXP-001 failed and is preserved; EXP-001R passed.
2. **CEXP-1 run complete,** with its receipt published. CEXP-1 has not been run. DEXP-1's Reuse learner copies Claim C's admission rule, which CEXP-1 measures first.
3. **An admissible program description code** in the bound profile. Turing-profile-v1.1 admits table models only.
4. **A generator for the bounded program family F.** No such generator exists in any repository checked on 2026-09-30.

**No result from DEXP-1 is a Physics Zero claim.** DEXP-1 maps discovery on synthetic program worlds. It says nothing about physical law.
