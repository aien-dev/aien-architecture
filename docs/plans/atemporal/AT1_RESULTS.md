## 3. What the evidence supports, in one paragraph

The AT-1 software (engine, oracle, evaluator, runner) conforms to `AT1_SPEC.md` and the frozen AT-1 contracts on 12 public positive classes, 12 negative classes, 72 refusal classes and 21 withheld cases, with three code bases built on different methods agreeing on every discrete verdict, with the ideal relational prediction failing exactly where and with exactly the code the specification says, and with the same `verdict_id` on 24 of 24 public cases on two machines with different operating systems, compilers and libm. That is a software conformance and cross-platform reproducibility result. It says the interacting construction was implemented as specified and runs the same way on a second machine; it does not say that a second party evaluated it, and it does not say the construction describes nature.

## 4. Limitations

1. One operator. Every agent is a session of one human operator's AI orchestrator, under one GitHub account; the Mac run was driven over ssh from the Spark. The separation is by machine, by commitment digest and by folder ownership, not by identity (charter section 3 item 6; open item 1 of charter section 10).
2. The evaluator on the Mac is Agent 4's evaluator rebuilt there, not a fourth code base (charter section 3 item 7). Engine, oracle and evaluator were all written from the same `AT1_SPEC.md`; a common error in the spec would pass all three. The spec's tables were recomputed independently with arbitrary-precision rationals by Codex before merge, which reduces but does not remove that risk.
3. Two platforms, both arm64: aarch64 Linux (glibc, gcc 13.3, rustc 1.98.1, GNU Make 4.3, dash) and macOS 26.6.2 arm64 (Apple clang 17, rustc 1.97.1, GNU Make 3.81). No x86_64 run; the Rust raw-syscall mutant has no x86_64 macOS form (Agent 5, Q8).
4. Mac build substitutions, no source edited: `sh` was dash through a PATH shim (macOS `/bin/sh`, bash 3.2.57, rejects `integration/run.sh` line 338); `nm` was llvm-nm 22.1.6 (Apple nm cannot read rustc 1.97.1 objects); `CC` was a wrapper refusing `-fsanitize`. The run is therefore a replication with those tools, not on a stock Mac.
5. The ASan and UBSan leg of the engine tests did not run on the Mac (an empty program built with `-fsanitize=address` hangs at startup on macOS 26.6.2); the plain tests ran (1390 passed, 0 failed). `make asan` has no time limit, so the hang blocked run 1 with no exit.
6. Bounds are ESTIMATED; nothing here is interval-rigorous. The cross-platform one- or two-ulp differences on P5 and N1e are inside the bounds, but they show that bit-level values are platform-dependent where the inputs have large denominators.
7. Isolation scans see compute objects only: named symbols plus the counter and syscall instruction patterns. Function pointers, dynamic loading and code outside the scanned objects are not seen. D2 exempted one symbol (`fwrite`) in one object for the frozen run.
8. Mutant power: only two mutants (drop V, wrong level) are compiled from the real engine; the rest of the 244-cell receipt acts on the evaluator's synthetic candidate. Blindness is structural and predicted (zero coupling, real relative phase, trivial kernel); a fault that only shows on an untested class would not be caught.
9. Model scope: clock-diagonal couplings only (`PAGE_WOOTTERS_FINITE_CLOCKDIAG`), one qubit, `N <= 64`, `M <= 256`. Couplings that are not diagonal in the clock energy basis, larger systems and automatic clock discovery are untested.
10. Agent 4's own withheld set (27 cases, commitment `91ad47bf...5c38` in `evaluator/HIDDEN_COMMITMENT.txt`) was never revealed or run in the frozen record; the Spark runs did not read any withheld case (QUALIFICATION.md Q7). Only Agent 7's 21 withheld cases were run, on the Mac only, so there is no cross-machine `verdict_id` comparison for withheld cases.
11. Judge independence: the runner's judge, the evaluator and the oracle agree, which shows a consistent reading of the contract, not that the reading is the only one. Six readings were settled by Agent 0 rulings on omega issue 371 without editing a frozen contract (c, d, e; ERROR label token; X7 `none` as the empty list; spliced `bound_kind` scope). Two of them are recorded as notes for a V2 contract.
12. Provenance times: the engine shim writes `run_started_utc` and `run_finished_utc` around the oracle call, before the engine computes; these fields are evidence only.

## 5. Decision on the next step

AT-1 meets its success criterion in the reproducibility sense: interacting-system results, specified failures of the ideal prediction included, are reproduced on a second machine with identical discrete verdicts, and are evaluated by a separate code base. It does not meet it in the sense of a separately operated evaluation (C10). The review therefore supports closing AT-1 as REVIEWED and recommends, before any AT-2 is chartered (items 3 to 5 follow the outside view's required controls, section 6):

1. Land the HELD post-freeze fixes as their own follow-ups, each without moving this record: PR 380 (D2), `run.sh` portability to bash 3.2, nm version and shell in `toolchain.txt`, a time limit on `make asan`.
2. Reveal and run Agent 4's committed 27-case withheld set on both machines, so withheld cases also get a cross-machine `verdict_id` comparison.
3. Apply the remaining spec section 9.2 mutants (flip V, phase sign, Y sign, axis swap, ideal marginal) to the real engine source, with killed and blind cells predicted before the run, as drop V and wrong level already are.
4. Add a shifted-system-clock control (the same inputs under a clock set years apart) and run the sanitizer leg on a platform where it works, so C9 and the Mac limit in section 4 item 5 are covered by measurement rather than by construction.
5. If C10 is to move from INCONCLUSIVE, a human-separated operator (Drake himself, or a non-Claude agent on the Mac under a second GitHub identity) must author the withheld set and run the replication; that is Drake's call (charter section 10 item 1), not something this program can produce by itself.

An AT-2 on couplings that are not clock-diagonal, or on automatic clock discovery (deferred by Drake), would be a software and model step only. Neither AT-1 nor any successor of this kind can promote C12; that would need evidence of a kind this program does not produce.

## 6. Outside view

One outside second opinion was obtained from Codex (`gpt-6-astra`) on 2026-10-10, on a self-contained brief carrying the model definition (AT1_CASE_V1 section 3), the worked example numbers (`p = 5/28, 1/4, 9/28, 1/4`), the positive case P2 and the negative cases N1 and N3, the gate results and the stated limits, plus one follow-up question on C9. The brief and the full answer are kept by the reviewer and quoted, trimmed, in the pull request that adds this file. It is cited here as an outside view, not as a co-author of this verdict.

Its findings:

- P2 is correct: removing a global phase, the conditional vector is proportional to `(5 - z, 3z)` with `z = exp(i pi k/2)`, `||phi_k||^2 = (7 - 2 cos(pi k/2))/80`, `||Psi||^2 = 7/20`, so `p(k) = (7 - 2 cos(pi k/2))/28 = 5/28, 1/4, 9/28, 1/4`; at `k = 1` the Bloch vector is `(-6/35, 30/35, 17/35)`, giving exactly `P(X+) = 29/70`, `P(Y+) = 13/14`, `P(Z+) = 26/35`; the other rows and the decoded engine values agree. Independent of the reviewer's derivation (section 2, C4) and in agreement with it.
- N1 is correct: the marginal alone differs from the ideal `1/4` by `1/14` at `k = 0, 2`, far above `10^-12`; failing the ideal comparison while passing the interacting one is consistent. N3 is correct: both surviving levels select `|0>`, `p(k) = 1/2, 1/4, 0, 1/4`, and conditioning at `k = 2` divides by zero, so `CONDITIONAL_UNDEFINED` is appropriate.
- Per claim: agrees with C1 to C8 and C10 to C12 as graded here. On C9 it first disagreed (INCONCLUSIVE, "no deliberate wall-clock variation is reported"), because the reviewer's brief had left out the repeatability control. On a follow-up giving that control (two passes 2 s apart under UTC and Asia/Tokyo on each machine, cross-machine runs about 35 minutes apart, no shifted clock tested) it revised C9 to "PASS within the tested conditions", with the limit wording now in C9. Both the first answer and the follow-up are quoted in the pull request.
- Cannot be concluded: correctness for all inputs, general clock-system interactions, complete isolation, or universal platform independence. Three implementations can share a mistaken specification. The unrevealed 27 cases supply no outcome evidence, and the Mac run supplies no sanitizer evidence.
- Controls it would require next, in order: (1) a separately controlled reviewer and withheld suite, deriving reference answers independently against the frozen candidate (section 5 item 5); (2) the remaining mutations applied to the actual engine, with detections and blind cells fixed before execution (section 5 item 3); (3) controlled wall-clock and environment variation, with the omitted sanitizer checks completed on a supported setup (section 5 item 4).

After the follow-up, the outside view and this review agree on every verdict in section 2.
